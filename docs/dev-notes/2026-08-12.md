## 一、玩法循环耦合（讨论稿 13 项优先级）

### Phase A 城镇深化（P1-P6，全部完成）

- P1 建筑升级生效 + 怪物材料接入升级消耗（仓库容量/职业名额/资源数随等级提升）。
- P2 住宅容量约束（没房子不能工作；住宅被毁释放居民与职业；夜晚回家亮灯）。
- P3 居民威胁广播 + 撤退插队（怪物生成时 EventBus 广播，撤退回家 ×1.2；受伤 3 天）。
- P4 居民移速 ±10% 个体差异（移速入存档）。
- P5 生活感第一层（回家关灯、空闲小动作）。
- P6 DebugManager 统一调试开关（蓝图解锁/跳过造价等）。

### Phase B 经济与防御（P7-P10，全部完成）

- P7 民兵营/箭塔 + 士兵站桩 AI（防御职业基类，数值场景配置）。
- P8 背包最简版本（装备槽 + 物品，ItemData .tres 数据驱动）。
- P9 商店建筑 + 装备数值（攻击/防御）+ 换装外观联动。
- P10 临时人口招募（金币/冷却/上限，DebugManager 门控）。

### Phase C 地下城（P11-P13）

- P11 地下城时间限制：城镇时间照常流逝，"距天黑"倒计时，超时强制入夜 + 晚归波次加强。
- P12 夜袭强度动态公式：天数基线 + 居民/建筑/囤积加成 ± 随机浮动，系数可配待实测调参。
- P13 地下城第一版 → 按反馈改为**两门二选一**：阶段制（默认 3 阶段 × 3 房间 + 阶段 BOSS），清房后左右两门选房间；居民救援房概率出现（每局上限 2，不保底）；商人固定阶段解锁（第 2 阶段 BOSS 后正式解锁商店蓝图）；死亡/放弃保留已救居民与解锁。

## 六、地下城时间流速调整（08-12 追加）

- 问题：`phase_length_seconds` 60 秒/阶段，白天+黄昏仅 120 秒地下城预算，探索偏紧。
- 方案：新增 `dungeon_time_scale = 0.5`（`game_config.tres` 可配，DayManager 启动时读取）；地下城内 DayManager 按倍率放慢（2 真实秒 = 1 城镇秒），城镇节奏不变。
- 关键修正：DungeonManager 倒计时改为每帧从 DayManager 阶段/剩余时间推导，删除独立递减——根治"只缩放 DayManager 会导致两套时钟脱同步、强制入夜提前掐断白天"的问题；`_force_night()` 保留作兜底，晚归波次加成语义不变。
- 状态联动：`enter_dungeon()` / `exit_dungeon()` / `reset()` 同步 `DayManager.set_in_dungeon()`，覆盖入口、出口、死亡、弃赛、通关全部路径；依赖保持 DungeonManager → DayManager 单向。
- 影响：仅地下城内计时速率；HUD 倒计时仍显示城镇秒数（消耗变慢）；存档格式与场景均不改。
- 测试：`test_dungeon_time` 重写（缩放生效、倒计时同步、强制入夜时机、晚归波次原用例保留），`test_game_config` 增加配置断言；全量测试全绿。
- 未决：0.5 手感需实测（必要时调低至 0.33，或与调大 `phase_length_seconds` 叠加）；HUD"时间变慢"提示文案待玩家反馈。
- 设计文档：`docs/design/2026-08-12-dungeon-time-scale-design.md`。
