# 《最后的篝火》总设计方案（v0.3）

> 状态：汇总文档（2026-08-10），汇总此前全部设计文档与实现记录，作为开发总纲；
> 随开发迭代更新。各子系统细节见文末"设计文档索引"。

## 1. 项目总览

- **类型**：2D 横版 · 建造经营 + 探索战斗 + 生存防御
- **参考**：《王国两位君主》（城镇经营与夜晚防御氛围）、《小骨英雄杀手》（玩家动作战斗）
- **核心概念**：玩家作为人类文明的开拓者，在未知世界建立据点。白天经营城镇（居民采集、建造、分配），夜晚抵御怪物；通过城镇的地下通道进入探索关卡打怪，获得金币与怪物材料，不断扩大文明。
- **玩家定位**：管理员 / 统筹者——不亲手采集，负责建建筑、分配职业、防守、探索战斗。
- **Demo 目标**：验证核心体验闭环——探索世界 → 战斗获取 → 建立据点 → 发展居民 → 守护文明。

## 2. 核心玩法循环

```
白天经营（建/升级建筑、分配居民） → 地下通道 → 探索关卡（战斗/掉落/解救居民）
          ↑                                              ↓
      天亮结算 ← 夜晚防御（怪物袭击建筑与居民） ← 回城自动入库
```

**无彻底失败**：玩家探索死亡回城镇；夜晚未守住，建筑损坏、居民受伤；最差情况建筑全毁，玩家仍可继续探索重建。篝火被毁是"最差状态"，重建即可恢复。

## 3. 系统设计汇总

### 3.1 时间系统

- 城镇时间：**白天 → 黄昏 → 夜晚** 三阶段自动轮转，每阶段默认 60 秒（可配）。
- 探索时间：暂停（玩家在关卡内不受城镇时间逼迫）。
- 调试：F9 推进一天、F10 推进一个阶段（避开编辑器 F5-F8）。

### 3.2 城镇与地图

- 手绘固定地图，玩家在 Godot 主场景（town.tscn）内直接绘制（TileMap/节点）。
- 城镇包含：建筑区、居民活动区、防御区、地下通道入口、临时堆点（无仓库时的入库兜底）。
- 地下通道：进入探索关卡的唯一入口（交互键 E），关卡选择面板待开发。

### 3.3 资源经济系统

- **EconomyManager**（Autoload）：全局库存 / 容量 / 出入库；入库受容量限制，建造扣费走 `withdraw`。
- **资源节点**（Area2D，无物理碰撞）：树 / 石头，按 `respawn_days` 重生；玩家与居民可自由穿过。
- **采集方式**：居民（对应职业）自动采集 → 捡掉落物 → 运回仓库 → 入库；玩家不手动采集。
- **城内资源**：伐木场/采石场在周围生成固定数量资源（建筑被毁时清理，重建后重新生成满编）。
- **城外资源**：`WildTreeSpawner` 在配置区域按 `max_trees` 限量随机生成，每天补足。
- **资源链**（与职业/建筑对称）：

| 资源 | 采集职业 | 职业建筑 | 资源生成建筑 | 重生天数 |
| --- | --- | --- | --- | --- |
| 木头 | 伐木工 | 伐木屋 | 伐木场 | 2 |
| 石头 | 矿工 | 矿工小屋 | 采石场 | 3 |

### 3.4 建筑系统

- **放置**：选建筑 → 半透明预览（绿=可建/红=不可建）→ 校验（不重叠/区域内/落地）→ 扣费生成。
- **统一基类 `Building`**：血量 / 损坏 / 修复 / 重建；"上线/下线"功能钩子保证被毁时功能失效、修复后恢复。
- **建筑清单与造价**（见第 5 节数值总表）。
- **升级**：所有建筑预留升级链（`upgrade_cost` / `upgrade_effect` 已配置），实际效果待开发。

### 3.5 居民系统

- **通用工作流**：IDLE → 找活 → 去工作 → 工作 → 捡取 → 运回 → 入库（职业策略模式，新职业不改通用流程）。
- **职业分配**：按建筑自动分配（建职业小屋后空闲居民自动转职）；每日可手动调整一次。
- **无职业居民**：家附近随机漫游，有空位自动转职。
- **受伤（非死亡）**：被怪物攻击失去 N 日工作能力（默认 2 天），释放职业名额，伤愈自动恢复。
- **人口**：开局 3 名居民；增长方式确定为**地下城解救**（待开发），不采用金币招募。

### 3.6 玩家系统

- **移动**：左右移动（A/D/方向键）、跳跃（空格/W/↑）。
- **战斗**：近战（J/左键，命中框 + 冷却）+ 弓箭（K/右键，投射物 + 冷却）；攻击力数据可配。
- **生命**：血条制（默认 100），受击 1 秒无敌；死亡 → 回篝火复活（篝火被毁则回临时堆点），无彻底失败。
- **背包与装备**：杀怪掉落金币/怪物材料，走过自动拾取入库；背包/装备系统占位，随地下城开发。

### 3.7 敌人系统

- **统一 `Enemy` + `EnemyData` 配置**：新怪物 = 新 `.tres` + 新视觉，不复制脚本。
- **状态机**：IDLE → CHASE → ATTACK → DIE；直线移动，复杂地形再上 NavigationAgent2D。
- **攻击优先级**（可配置）：如夜狼 `[villager, building, player]`；地下城怪可配 `[player]`。
- **夜晚波次**：夜晚阶段在城镇边缘生成一波怪物，强度随天数递增（`base 2 + (day-1) × 1`，上限 10）。
- **掉落**：按 `loot_table` 生成拾取物，玩家/居民靠近自动拾取入库。

### 3.8 城镇 UI

CanvasLayer 分层：常驻 HUD（顶栏）→ 面板（建造/建筑详情/居民/背包）→ 弹窗（确认/暂停）→ 通知（toast）。

- **顶栏**：玩家血条、天数+昼夜+倒计时、资源栏（木/石/金币/材料 + 容量）、居民栏（总数/受伤）。
- **建造菜单**：底部卡片列表，资源不足置灰。
- **建筑详情**：名称/等级/HP/职业名额/已分配居民；修复/重建/拆除（确认弹窗）；升级占位。
- **居民面板**：列表 + 转职选项（职业小屋名额/转空闲），每人每天限一次。
- **其他**：交互提示（E）、夜晚预警横幅、通知队列、暂停菜单（继续/设置占位/存档/读档/返回标题）、背包占位。
- **键位**：A/D 移动、空格跳、J 近战、K 弓、E 交互、B 建造、Tab 居民、I 背包、Esc 暂停、F9/F10 调试。

### 3.9 存档系统

- **格式**：JSON 单文件 `user://save_game.json`，版本 1，路径可注入。
- **时机**：城镇内每天天亮自动存档；暂停菜单手动存/读档；启动界面"继续游戏/新游戏"。
- **范围**：昼夜、经济（库存/容量）、玩家（位置/血量）、建筑（场景/位置/血量/损坏/等级）、资源节点（位置/血量/耗尽/重生/野生标记）、居民（名字/职业/位置/搬运/伤势）。
- **不保存**：活动敌人、居民运行状态、每日调整次数（加载后当天可重新调整）。
- **加载**：清场重建，恢复顺序 昼夜 → 建筑 → 资源 → 居民 → 玩家 → 经济（最后覆盖避免仓库扩容干扰）；加载后按建筑状态同步功能（容量/名额/场内资源）；场内资源由建筑自动重建，不单独存档。
- **兼容**：`migrate()` 预留版本迁移入口。

## 4. 技术架构

### 目录结构

```
├── docs/           # 设计文档与实施计划
├── assets/         # 原始素材（art/audio/fonts）
├── scenes/         # main/town/dungeon/player/villagers/enemies/buildings/resources/ui
├── scripts/        # autoload + 各系统模块（building/economy/enemy/player/town/ui/villager/...）
├── resources/      # 配置数据（data/，.tres）
└── shaders/        # 着色器源码
```

### 全局单例（Autoload）

| 单例 | 职责 |
| --- | --- |
| EventBus | 全局事件信号，系统间解耦 |
| GameManager | 场景切换、暂停、放置状态 |
| DayManager | 天数与昼夜阶段（调试键 F9/F10） |
| EconomyManager | 库存/容量/出入库 |
| TownRegistry | 城镇登记表（居民/职业建筑/每日调整），职业显示名 |
| SaveManager | 存档/读档（JSON，版本化） |
| AudioManager | BGM/音效统一入口（预留） |

### 2D 物理层约定

| 层 | 内容 |
| --- | --- |
| 1 | 世界（地面/墙壁等物理阻挡） |
| 2 | 玩家（mask 1\|4） |
| 3 | 居民 |
| 4 | 敌人（mask 1\|2，与玩家互相阻挡） |

资源/掉落物/攻击框用 Area2D，不参与阻挡。

### 设计原则

1. 数据驱动：建筑/居民/怪物/武器一律 `.tres` 配置，不写死在脚本。
2. 场景与逻辑分离：`.tscn` 与 `.gd` 一一对应。
3. 系统解耦：跨系统通信走 EventBus。
4. 玩法优先：先跑通核心循环再扩展内容。
5. 预留接口：等级/类型/属性/状态留扩展位。
6. 先设计后实现：新功能先归档设计文档再写代码（TDD，全套测试绿）。
